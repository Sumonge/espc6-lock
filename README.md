# espc6-lock

纯倒计时**时间锁**固件，无密码。跑在 Seeed XIAO ESP32C6 上，用 SSD1315 128x64 OLED
显示，靠舵机拨动一个机械锁舌。

```
空闲(开锁) --K3--> 倒计时中(锁定) --归零--> 空闲(开锁)
```

## ⚠️ 设计前提：这不是安全设备

**计时状态不做持久化。** 上电一律回到「空闲 = 开锁位」，也就是说拔电重启就能绕过锁定。
舵机因此是 fail-open 的：掉电、复位、固件崩溃，锁都是开的。

这是刻意的选择——本设备的定位是**定时器**，不是锁具。要真正防拆，得加上
状态存 NVS + 上电先回锁定位，那样又会引入「电池耗尽后永久锁死」的问题。
在改这个语义之前，别把它用在任何有实际安全含义的场合。

## 硬件

| 元件 | 型号 |
|---|---|
| 主控 | Seeed XIAO ESP32C6 |
| 显示 | SSD1315 128x64 I2C OLED（0.96"），板上带 K1~K4 四个按键 |
| 执行器 | 舵机 + 机械拨片/锁舌 |

### 接线

| 屏幕/外设 | 接到 XIAO | GPIO |
|---|---|---|
| GND | GND | — |
| **VCC** | **3V3** | — |
| SCL | D5 | 23 |
| SDA | D4 | 22 |
| K1 | D0 | 0 |
| K2 | D1 | 1 |
| K3 | D2 | 2 |
| K4 | D3 | 21 |
| 舵机 信号 | D8 | 19 |
| 舵机 VCC | **外部 5V 电源** | — |
| 舵机 GND | 外部电源 GND，**并与 XIAO 共地** | — |

> **屏幕 VCC 必须接 3.3V，不能接 5V。**
>
> **舵机不要从 XIAO 的 5V 脚取电。** 舵机堵转电流轻松上到几百 mA，会拉垮
> XIAO 的供电导致反复重启。用独立 5V 电源，且 GND 必须和 XIAO 共地，
> 否则 PWM 信号没有参考电位，舵机会乱抖。

## 操作

### 待机（开锁，正在设时长）

| 按键 | 作用 |
|---|---|
| K1 | 时长 + |
| K2 | 时长 − |
| K3 | 启动倒计时 → 上锁 |
| K4 | 归零重设 |

加减有两种方式：

- **单击** 1 分钟
- **按住** 自动连发，步进随按住时长变大（避免设 2 小时要按 120 下）
  - 按住 < 2 秒 → 每次 1 分钟（精确调节）
  - 按住 2~5 秒 → 每次 5 分钟
  - 按住 > 5 秒 → 每次 15 分钟
- **双击** 直接跳 1 小时。这一档刻意不参与连发加速——1 小时是「双击」这个
  离散动作换来的，要 3 小时就双击 3 次。

时长上限 1440 分钟（24 小时）。

### 倒计时中（锁定）

**长按 K4 满 5 秒**才能取消。刻意不用「按下就取消」，否则一碰就解锁了。

按住期间画面会切成紧急解锁界面：第 1 段变「紧急解锁中」，第 2、3 段是
脚丫 + 羽毛动画（羽毛随按住时长向右飘），第 4 段是一条 1px 进度条，
实线是已走过的部分、点线标出剩余轨道。

## 屏幕布局

128x64 横向四等分，每段 16px：

```
┌────────────────────────────┐
│ 第 1 段  标题／状态         │  ← 下面一条分隔线
├────────────────────────────┤
│                            │
│ 第 2+3 段  大号 HH:MM:SS    │  ← 跨两段显示，共 32px
│                            │
├────────────────────────────┤
│ 第 4 段  提示               │  ← 待机时留空
└────────────────────────────┘
```

秒数总是 `:00`——时长只能按整分钟设定。

## 编译与烧录

依赖 **U8g2**（Arduino IDE 库管理器搜 "U8g2"）。舵机用板载 LEDC 直接产生
50Hz PWM，不需要 Servo 库。

命令行（`arduino-cli` 随 Arduino IDE 2.x 一起装）：

```bash
CLI="/c/Program Files/Arduino IDE/resources/app/lib/backend/resources/arduino-cli.exe"

# 编译
"$CLI" compile --fqbn esp32:esp32:XIAO_ESP32C6 --warnings all .

# 烧录（端口自己换，用 "$CLI" board list 查）
"$CLI" upload -p COM4 --fqbn esp32:esp32:XIAO_ESP32C6 .
```

用 IDE 的话直接选板子 `XIAO_ESP32C6` 然后点上传即可，不需要额外设置。

开串口监视器（115200）能看到按键日志、状态迁移和每 5 秒一行的心跳。
**开机时会做按键体检**：把四个按键脚配成 `INPUT_PULLUP` 后读一次空闲电平，
没按时必须是 HIGH；哪个脚开机就是 LOW，说明它被短路到 GND 了，多半是接线问题。

## 首次装好后必须标定

`SERVO_US_UNLOCK` / `SERVO_US_LOCK` 两个脉宽（默认 1000 / 2000 µs）是按常见
舵机给的估值，**没有在实机上验证过**。装上拨片后按实际行程调：

- 数值调大 → 往一个方向多转，调小 → 往反方向多转
- 舵机在某个位置发出持续「吱吱」声或发热，说明顶到机械限位了，
  把对应数值往中间调 50~100 µs

## 版本控制

仓库：<https://github.com/Sumonge/espc6-lock>（私有）

首次推送时用的（`gh` 已登录的前提下，一条命令建仓库 + 关联 + 推送）：

```bash
gh repo create espc6-lock --private --source=. --remote=origin --push
```

没有 `gh` 时的等价手动流程：

```bash
# 1. 网页上建空仓库。关键：不要勾 README/.gitignore/LICENSE，
#    否则远程先有一个提交，跟本地历史对不上，首次 push 会被拒。
git remote add origin git@github.com:Sumonge/espc6-lock.git
git push -u origin main
```

> 如果第 1 步不小心勾了，`git push` 会报 `rejected (fetch first)`，用
> `git pull --rebase origin main` 把远程那个提交垫到本地历史下面，再 push。

日常循环：

```bash
# 改完 .ino 先编译确认能过，再提交
git add -A
git commit -m "把脚丫镜像成左脚"
git push
```

remote 走 SSH（`git@github.com:...`），`gh` 的登录走 HTTPS token，两者互不干扰。
换台机器 clone 时要么把 `~/.ssh/id_ed25519` 带过去，要么改用 HTTPS 地址 + PAT。
